# 安全与权限

Web API 的可用性受到浏览器安全模型约束。接口存在并不代表当前页面一定有权调用，协议、来源、嵌入关系、用户授权和用户操作都可能改变结果。

## 核心边界

| 机制 | 解决的问题 |
| --- | --- |
| 同源策略 | 限制不同来源之间读取数据和操作对象 |
| CORS | 由服务器声明哪些跨源读取可以被允许 |
| 安全上下文 | 将敏感能力限制在 HTTPS 等可信环境 |
| Permissions API | 查询部分能力当前的授权状态 |
| Permissions Policy | 控制页面和 iframe 可以使用哪些能力 |
| 用户激活 | 要求调用发生在点击、按键等真实用户操作之后 |
| CSP | 限制页面可以加载和执行的资源 |

## 使用原则

- 把权限拒绝、权限被撤销和接口不可用视为正常分支。
- 只在实际需要时申请权限，并说明用途。
- 不要把 CORS 当成身份认证或服务端访问控制。
- 对跨窗口消息验证 `origin` 和消息结构。
- 对剪贴板、媒体设备、文件和硬件能力采用最小权限原则。

安全限制通常横跨多个 API，应在每个专题中同时说明，而不是只集中在本目录。
